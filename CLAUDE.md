# Animal Crossing: City Folk Recompiled (PC port) — working notes

## Goals
- Native PC port of Animal Crossing: City Folk (Wii; JP "Machi e Ikou yo: Doubutsu no Mori"), built like our Luigi's Mansion port (sibling repo `C:\Users\rmelv\Desktop\Lugis Mansion PC Port`, "LM" below; Super Mario Sunshine port `C:\Users\rmelv\Desktop\Mario Sunshine PC Port`, "SMS"): a build-time PPC→C++ recompiler + HLE'd SDK on the Aurora engine (WebGPU/Dawn + SDL3). City Folk is a **Wii** game: the engine needs the Wii parts listed in docs/WII.md.
- Discs: USA **RUUE01 rev 1**, PAL **RUUP01 rev 1**, Japan **RUUJ01 rev 1**, Korea **RUUK01 rev 1** (extracted partitions in `US DATA/`, `PAL DATA/`, `JAPAN DATA/`, `KOREA DATA/` (+ the user's RVZ there; its partition boot.bin says rev 0, the outer header 1): `DATA/` = game partition with sys/ + files/, `UPDATE/` = system update partition, unused). Base version: USA; PAL, Japan and Korea selectable like LM's PAL base.
- Same core goals as LM: console-accurate rendering first (EFB copies incl. to RAM, Z textures, TEV/indirect precision, fog, copy filters), then every enhancement scales on top: any frame rate (interpolation, logic at the game's rate), any resolution, widescreen (the game supports 16:9 natively) + ultrawide, MSAA, F1 overlay menu (Visuals / Sound / Controls / Enhancements; Esc closes), settings in `%APPDATA%\Animal Crossing City Folk Recompiled\settings.ini`. Costly accuracy features get toggles in F1 > Visuals > Rendering, ON by default.
- Game enhancements (docs/ROADMAP.md): Wii pointer from mouse / right stick / gyro; normal controller navigation of menus without the pointer; grass wear (Original / New Leaf style / Off); skin tone picker for the current player only; region-exclusive content in every version (docs/REGION_CONTENT.md); hemisphere toggle; real-time weather for a town picked by name (opt-in, internet); online play restored via revival services (docs/ONLINE.md). Everything optional OFF / original by default.

## Reuse from LM
- LM is the reference implementation. Carry over its generic parts (recompiler, runtime/Ctx, scheduler, HLE SDK, frame pacing, interpolation, EFB copy, widescreen, precache, controls, settings/menu framework, setup flow, updater, Aurora submodule + patches) and strip LM-specific code, as SMS did. Game-specific code goes in `src/game/`. Keep shared code close enough that fixes port both ways; log generic fixes made here in `docs/BACKPORT.md` (what, files/patches, status). Never edit the LM or SMS repos from here.
- Aurora patches: same series as LM (same file names and contents), City Folk-only patches in the **0300+** range, kept generic so LM/SMS can adopt them.

## Release requirements
- Same model as LM: ship the recompiler + bundled clang/lld; first run asks for the user's own disc image (Wii ISO/WBFS/RVZ/CISO, or a Dolphin "Extract Entire Disc" folder), recompiles the DOL and all RELs into a game module in AppData, validated by hash. End users never run scripts. Every disc already carries every region's holidays, event text and items (docs/REGION_CONTENT.md), so region content needs no second disc; only Korean names and Nintendo-distributed items come from elsewhere.

## Test runs (same rules as LM)
- **Load limits (several agents share this PC; 2026-10-28 the PC was overloaded by hundreds of compiler processes and had to be restarted):** builds with at most 6 parallel jobs (`CMAKE_BUILD_PARALLEL_LEVEL=6` / `ninja -j6`; the game-module build in CityFolkRecomp setup also uses all cores, so don't run setup tests while building), several game instances are fine, but a run that compiles shaders (cold cache) or a setup module build must run alone (tell the coordinator first; reuse a warm scratch cache dir across runs), no background loops that launch runs unattended, and stop every process you started before you finish.
- **Start from a save, not a new game**: fixture `user-town` (the user's own town "Frun", tutorial done, house, USA; `out/fixtures/user-town/nand`, gitignored, never commit or modify it) with `CF_FIXTURE=user-town` + `--input @tools/routes/continue.txt` (`CF_INPUT_CLOCK=frames`): title -> Rover -> "Preparing saved data" -> in town at the house by ~frame 5000 (Resetti greets first: the game introduces him at the first reload after the first save). ## Gotchas (from LM/SMS)
- Don't write C/C++ with `\n` escapes through bash heredocs/python-in-bash: use the Write/Edit tools. Python files with `encoding="utf-8"`.
- Timing matters: instantaneous hardware completion breaks game assumptions (DVD/NAND/IPC replies need modelled latency).
- Paths contain spaces: quote them.

## Audio (branch ax-audio; docs/AUDIO.md)
- `src/recomp/audio_dsp.cpp` = stand-in for the game's **AX DSP microcode** (image 0x80542900, 0x2000 bytes; read with LM's `tools/dsp_disasm.py`): processes AX's 3 ms command lists (96 samples at 32 kHz) and the 0x140-byte PBs as the microcode does; NW4R snd / AX / AXFX run unchanged. `hle_audio.cpp`: DSP task HLE (list mixed at its mail, resume callback after `CF_AX_DSP_US`, default 400) + LM's AI pacing. Only the polyphase coefficient ROM is ours.
- Test: `CF_AUDIO=0 CF_AUDIO_WAV_RAW=<file>` (AI stream, left first), `CF_AUDIO_WAV=<file>` (device output incl. Remote speaker / 5.1), `CF_AUDIO_LOG=1|2` (voice starts with kind + player, per-second levels/clipping/kinds, aux callbacks, AX mode, `[rmt]` Remote speaker bursts), `CF_AUDIO_KIND_LOG=1`, `CF_RMT_DUMP=<file>`, `CF_AX_TRACE=<PB addr>`, `CF_AX=0` (no mixing, A/B), `CF_IRQ_STALL=1 CF_TRACE=ring` (slow interrupt handlers). Slider checks: `CF_SETTINGS_AT="5000:audio.music_volume=0;..."`.
- Volume sliders (branch audio-2): per voice in the DSP stand-in, by the NW4R sound player that owns it (AXVPB -> AxVoice -> Voice -> Channel/StrmPlayer -> sound -> SoundPlayer index = rv_forest.brsar player id; music 21-25, voices 15/16, rest effects). Wii Remote speaker: `src/recomp/audio_remote.cpp` decodes WPADSendStreamData (Yamaha ADPCM, high nibble first, 6 kHz) and mixes it centred (own slider). Surround: the game forces stereo; discrete 5.1/7.1 keeps DPL2 via hooks.txt patch 30. docs/AUDIO.md.
